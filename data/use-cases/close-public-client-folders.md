# close_public_client_folders.py - заменить публичную ссылку на именной доступ

## Зачем

Папки клиентов, открытые "для всех, у кого есть ссылка", закрываются не одним движением. Сначала клиенту выдаётся именной доступ на его почту, и только потом снимается право `anyone`. Скрипт делает это по одной папке и пишет строку аудита на каждую.

Порядок принципиален: для большинства клиентов публичная ссылка - единственный способ попасть в свою папку. Снять её первой означает отрезать клиента от его же материалов.

## Когда применять

- Аудит нашёл папки клиентов с правом `anyone` (`policy_is_public_anyone == True` в `files.csv`).
- Закрытие волнами: сначала клиенты с gmail (адрес уже является Google-аккаунтом, именной доступ просто работает), остальные домены - позже, после разговора с клиентом.

## Что на входе

CSV сопоставления "папка - контакт Планфикса", его собирает скрипт `map-public-drive-folders.ts` в репозитории planfix-api-client. Обязательные колонки: `folder_id`, `contact_email`. Дополнительно в лог попадают `drive_client_name` и `contact_id`.

Сервисному аккаунту нужны права управления доступом на общем диске (`organizer` или менеджер контента).

## Как запускать

```bash
# Предпросмотр всей gmail-волны, ничего не меняется
.venv/bin/python close_public_client_folders.py

# Первая партия из трёх, дальше проверить руками
.venv/bin/python close_public_client_folders.py --apply --limit 3 --log data/close-wave1-batch1.csv

# Остальные (уже закрытые папки пропускаются при повторном запуске)
.venv/bin/python close_public_client_folders.py --apply --log data/close-wave1.csv
```

Ключевые флаги: `--apply` (без него только предпросмотр), `--all-emails` (снять ограничение на gmail), `--role` (по умолчанию `commenter`), `--limit`, `--pause`, `--log`, `--config`.

## Что на выходе

- CSV аудита: `folder_id, client_name, contact_id, email, grant, revoke, status, details`. Статусы: `preview`, `closed`, `already_closed`, `grant_failed`, `revoke_failed`.
- `data/close_public_client_folders.log` - полный лог.
- В Google Drive: почта клиента добавлена как `commenter`, право `anyone` удалено.

## Особенности

- Состояние папки читается из API перед каждой операцией, поэтому запуск идемпотентен: папка без права `anyone` помечается `already_closed` и пропускается. Повторный запуск после прерванного - безопасен.
- Если выдача именного доступа упала, ссылка не снимается. Строка помечается `grant_failed`.
- Письмо клиенту Google не отправляет (`sendNotificationEmail=False`). Предупредить клиента - отдельное человеческое решение.
- Лог сбрасывается на диск после каждой строки, прерванный запуск оставляет пригодный след.

## Грабли

- **Не расширять `--all-emails`, не посмотрев на домены.** Именной доступ Google работает только на Google-аккаунт. Выдать `commenter` на `client@mail.ru` означает не выдать ничего, а снятие ссылки после этого отрежет клиента.
- Срок действия тут не поможет: `expirationTime` в Drive API принимается только для прав `user` и `group`, а на папках только с ролью `reader`. Ни "ссылки со сроком", ни "временного комментатора на папку" не существует.
- CSV сопоставления протухает: папки появляются и закрываются между запусками. Для новой волны его надо пересобрать, а не переиспользовать старый.
- Строки с пустым `contact_email` отбрасываются при чтении и в лог не попадают. Если нужно знать, сколько отброшено, сравнивай с числом строк на входе.
